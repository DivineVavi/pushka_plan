# «Пушка-план»

MAX-бот и мини-приложение, которое составляет персональный предварительный план мероприятий из подготовленного снимка афиши Пушкинской карты. Пользователь указывает город, возраст, вручную учтённый остаток, интересы и свободные даты; приложение предлагает три варианта плана и помогает пересчитать его после ручной отметки о покупке.

> **Данные не обновляются в приложении.** В комплект входит подготовленный SQLite-снимок публичной московской афиши Культура.РФ с сохранёнными источником и временем получения. Это не живая интеграция: сведения могут быть устаревшими. Даты и цены в плане — опубликованные значения и плановые ориентиры; пользователь самостоятельно проверяет конкретный сеанс, наличие билетов и итоговую цену на странице события. Приложение не видит банковский баланс и не принимает оплату.

## Пользовательский сценарий

1. `/start` в боте показывает приветствие и кнопку **«Открыть планы»**. На остальные сообщения бот отвечает предупреждением, что управление в чате недоступно, и предлагает ту же кнопку.
2. В мини-приложении пользователь указывает город, возраст 14–22 года, вручную учитываемый остаток 0–5000 ₽, срок планирования, свободные даты и интервалы, интересы и максимум событий.
3. Приложение показывает три варианта: **«По интересам»**, **«Больше впечатлений»** и **«Почти без остатка»**. Геолокация и настройки времени на дорогу скрыты.
4. В карточке видны дата, время, площадка, возрастная маркировка, причины выбора и плановая цена. Цена с пометкой **«от N ₽»** — опубликованный минимум, а не обещание цены покупки.
5. Пользователь проверяет сеанс и билеты на странице события. После покупки вручную отмечает её и вводит фактическую цену; приложение учитывает покупку и пересчитывает остаток плана.

Профиль, сравнение вариантов, выбор плана и отметка покупки доступны только в мини-приложении. Бот нужен для входа в него и, при подключённом MAX, доставки уведомлений.

## Снимок каталога и сохранение данных

В репозитории находится `data/catalog-snapshot.sqlite3` — подготовленный снимок московской афиши. В нём только данные публичного каталога, без профилей и покупок. В метаданных SQLite сохранены источник `https://www.culture.ru/afisha/moskva/pushkinskaya-karta` и время получения `2026-09-28T20:54:34.601079+00:00`. Снимок содержит **1 753 мероприятия, 1 786 площадок и 6 786 сеансов**; исходные даты сеансов сохранены без сдвига, последние доходят до **27 декабря 2026 года**. Эти данные не обновляются при запуске: снимок не является живым каталогом, а его свежесть не подтверждается; считайте его устаревшим.

При первом запуске каталог из снимка загружается в рабочую SQLite-базу, только если в ней ещё нет метаданных каталога. Последующие запуски не перезаписывают каталог и пользовательские данные. В Docker рабочая база расположена в `/var/lib/pushka/pushka.sqlite3`, а именованный том `pushka-data` сохраняет каталог, профили и покупки при пересоздании контейнера.

Для подготовки нового **каталожного** снимка из рабочей базы предусмотрен экспортёр `pushka.snapshot`. Он открывает исходную базу только для чтения и формирует отдельный файл только с публичным каталогом — мероприятиями, площадками, сеансами и метаданными, без профилей и покупок:

```bash
python3 -m pushka.snapshot \
  --export data/pushka.sqlite3 \
  --output data/catalog-snapshot.sqlite3
```

Не заменяйте снимок копией всей рабочей базы: в ней хранятся пользовательские данные и настройки приложения.

## Быстрый запуск в Docker

Нужны Docker Engine и Docker Compose v2. `.env` для запуска не обязателен. При сборке Vite создаёт production-интерфейс в отдельном Node.js build stage; контейнер приложения использует Python runtime.

```bash
docker compose up --build -d
```

- Мини-приложение: <http://localhost:8000>
- Проверка состояния: `curl http://localhost:8000/health`
- Логи: `docker compose logs -f pushka`

По умолчанию порт доступен только на `127.0.0.1`. Переменные для локальной настройки перечислены в [конфигурации](#конфигурация); безопасный шаблон находится в `.env.example`. Храните секреты только в локальном `.env` и не добавляйте их в Git.

### Разработка интерфейса

Нужны Python 3.12, Node.js 22+ и npm. В первом терминале запустите API из корня репозитория:

```bash
python3 -m pushka.server
```

Во втором установите JS-зависимости и включите Vite:

```bash
npm ci
npm run dev
```

Откройте <http://localhost:5173>. Vite обслуживает `frontend/` и проксирует запросы `/api` на сервер `localhost:8000`. Production-сборка интерфейса запускается командой `npm run build` и создаёт файлы в `static/`.

## Сборка и runtime

- **Frontend build:** Node.js 22+, npm, React, `@maxhub/max-ui` и Vite. Версии JS-зависимостей зафиксированы в `package-lock.json`.
- **Runtime:** Python 3.12 и стандартная библиотека, включая SQLite. Node.js и npm в runtime-образ не устанавливаются.
- **Хранение:** SQLite в рабочей базе; Docker Compose сохраняет её в томе `pushka-data`.
- `requirements.txt` оставлен как заметка о runtime: сторонних Python-пакетов нет.

## Конфигурация

Скопируйте `.env.example` в `.env`, только если нужно изменить настройки. Все секреты должны оставаться локальными.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `CATALOG_SNAPSHOT_PATH` | `/app/data/catalog-snapshot.sqlite3` в Docker | Путь к подготовленному снимку, используемому для начального заполнения каталога |
| `MAX_BOT_TOKEN` | пусто | Токен MAX-бота; без него доступен локальный запуск в браузере |
| `MAX_WEBHOOK_SECRET` | пусто | Обязателен при заданном `MAX_BOT_TOKEN` для проверки webhook |
| `MAX_WEB_APP_ID` | `t99_hakaton_max_bot` | Имя пользователя MAX-бота для кнопки открытия приложения. Это историческое имя переменной; укажите username своего бота |
| `PUBLIC_URL` | пусто | Публичный HTTPS-адрес сервера для регистрации webhook |
| `PUSHKA_BIND_IP` | `127.0.0.1` | IP-адрес хоста, на котором публикуется контейнерный порт |
| `PUSHKA_HOST_PORT` | `8000` | Порт приложения на хосте |
| `ADMIN_TOKEN` | пусто | Необязательный токен доступа к `GET /api/admin/status` |
| `DEMO_COOKIE_KEY` | пусто | Необязательный ключ подписи cookie локальной браузерной сессии; если не задан, ключ сохраняется в рабочей базе |

Рабочая база в Docker задана как `/var/lib/pushka/pushka.sqlite3` и хранится в томе. Для локального запуска Python-сервера путь по умолчанию — `data/pushka.sqlite3`.

## MAX-бот

Чтобы подключить своего бота, создайте его в MAX и задайте в локальном `.env` `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET` и публичный `PUBLIC_URL`. `MAX_WEB_APP_ID` должен содержать username бота, используемый кнопкой `open_app`. Для регистрации webhook выполните:

```bash
docker compose exec pushka python -m pushka.setup_max
```

В настройках бота вручную привяжите публичный HTTPS-адрес мини-приложения. Затем проверьте `/start`, открытие приложения и уведомления в мобильном и веб-клиентах MAX. Локальный запуск в браузере не заменяет проверку в настоящих клиентах MAX.

## Проверки

Python-тесты запускаются через `unittest`:

```bash
python3 -m unittest discover -s tests -v
```

Для браузерных UI-тестов используйте `npm run test:ui` после установки зависимостей; скрипт собирает интерфейс перед запуском Playwright. В Docker-образ также включены тесты, и их можно запустить так:

```bash
docker compose run --build --rm --no-deps pushka python -m unittest discover -s tests -v
```

## Остановка и сброс

```bash
docker compose down      # остановить контейнер; том и данные сохраняются
docker compose up -d     # запустить снова
docker compose down -v   # полный сброс: удаляет том с каталогом, профилями и покупками
```

`down -v` необратимо удаляет пользовательскую базу. При следующем запуске каталог будет заново загружен из подготовленного снимка.

## Ограничения

- Данные взяты из подготовленного снимка и не обновляются при работе приложения; считайте их устаревшими, даты сохранены как в исходном каталоге.
- Остаток вводится пользователем и не является банковским балансом Пушкинской карты.
- Минимальная цена не гарантирует цену покупки, наличие билетов или доступность сеанса.
- Отметка «Купил» и фактическая цена вводятся пользователем вручную; оплаты внутри приложения нет.
- Снимок московский и не представляет собой актуальную афишу всей страны.
